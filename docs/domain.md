# 经营权流转协商台领域约定

项目面向集体林权改革与林下产业协作场景，业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够追溯到采用的数据版本。

## 角色

| 角色 | 标识 | 权限 |
| --- | --- | --- |
| 村集体管理员 | `village_official` | 维护农户/地块/成员资料，查看全部明细与审计留痕，处理异议，宣布进入签署 |
| 项目公司 | `enterprise` | 发起并修订自己名下的方案，只能看到聚合统计，看不到家庭级资料 |
| 农户成员 | `villager` | 查看本组范围内的方案，以户为单位表态、提异议、退出地块，只能看到本户资料与聚合统计 |

内置引导账号 `official-root`（村集体管理员），部署时应替换为受控账号体系。HTTP 层通过 `x-actor-id` 请求头识别身份。

## 核心规则（全部为确定性规则）

### 版本绑定

- 方案的全部条款（价格、租期、保底收益、退出条件）构成一个**文本版本**；表态与异议都挂在提交时的当前版本上。
- 企业改价产生新版本后，旧版本上的表态与异议保留留痕，但不再计入法定人数；农户需在新版本上重新表态。
- 改价必须携带 `expectedVersion` 做乐观并发控制：两个并发改价请求，先落库者生效，后到者确定性返回 `VERSION_CONFLICT`。

### 法定参与条件（默认双三分之二，可按方案配置）

- 应参与户 = 方案范围内仍有地块的户；参与户 = 当前版本上存在有效表态的户；同意户 = 最新有效表态为「同意」的户。
- 一户多人先后表态时，以序号最新的一条有效表态确定该户立场。
- 判定全部使用整数比较：`参与户 × 分母 ≥ 应参与户 × 分子` 且 `同意户 × 分母 ≥ 参与户 × 分子`。
- 只有达到法定参与条件，村集体才能让方案进入签署（`enter-signing`）；进入签署时把当时版本定为最终文本并留痕。范围内已无符合条件的户时返回 `NO_ELIGIBLE_HOUSEHOLDS`。

### 委托授权

- 委托按「委托人 + 受托人 + 事项（表态/异议/退出地块）+ 方案范围 + 截止时间」建立；同一对人之间同时只允许一条有效委托。
- 代为操作时依次校验：授权存在 → 未撤销（`DELEGATION_REVOKED`）→ 未到期（`DELEGATION_EXPIRED`）→ 事项在范围内（`DELEGATION_SCOPE`）→ 方案在范围内（`DELEGATION_SCOPE`）。
- 时间边界一律含端点：到期时刻仍有效，过一刻即失效；协商截止时刻同理。
- 委托到期或撤销不影响其在有效期内已作出的表态。

### 表态与撤回

- 同一委托人在同一版本上重复提交相同内容：幂等返回原记录；内容不同：`DUPLICATE_STATEMENT`，须先撤回再重新表态。
- 表态、撤回、退出地块、改价只允许在协商截止之前；截止后一律返回 `DEADLINE_PASSED`，村集体可据既定结果评议并进入签署。
- 异议在方案签署前均可提出、处理或撤回，全程留痕。

### 少数地块退出

- 农户可在截止前退出本户名下、且在方案范围内的地块；退出他人地块（`NOT_PLOT_OWNER`）或范围外地块（`PLOT_NOT_IN_SCOPE`）被确定性拒绝。
- 部分退出不影响该户参与资格；全部退出后该户移出应参与基数，其历史表态留痕但不再计入。

### 隐私边界

- 家庭级明细（逐户立场、逐户地块归属、审计留痕）仅村集体可见。
- 农户只能看到本户资料与聚合统计；异议提出方对其他农户匿名化（仅显示角色与村民小组）。
- 企业只能看到自己名下方案与聚合统计，看不到任何家庭级资料；范围外的农户与其他企业按「方案不存在」（404）处理，不泄露方案存在性。

## 数据与运行

- 业务数据默认保存在内存中；设置环境变量 `DATA_FILE` 后，每次写操作将全量状态原子落盘（临时文件 + 改名），重启自动恢复。
- 所有写操作都会追加一条审计事件（单调递增序号、操作人、时间、关联方案），审计仅村集体可查。
- 时间由可注入的时钟提供，测试中以固定时钟验证到期、截止等时间规则。
